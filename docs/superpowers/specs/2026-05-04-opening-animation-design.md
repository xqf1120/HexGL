# HexGL 开屏动画升级设计

日期：2026-05-04

## 目标

在不改变游戏核心玩法、操控、赛道加载与比赛流程的前提下，为当前首页入口增加一段约 10 秒的科技 3D 开屏动画。动画完成后回到首页菜单，用户再点击 Start 进入原有流程。

本次设计只覆盖首页/开屏层，不改动游戏本身的运行逻辑。

## 用户体验目标

- 首次进入页面时，先播放一段可观赏的开屏动画。
- 开屏整体风格为“霓虹赛博 + 未来竞速”。
- 镜头顺序为：城市环境建立 → 低空掠过赛道 → 飞船超近景掠过 → 引擎拉满与火花 → 科技转场回首页菜单。
- 开屏总时长控制在 10 秒左右。
- 开屏播放过程中，用户可随时点击“跳过”，立即进入首页菜单。
- 开屏结束后，首页菜单仍保留轻微动态待机感，但不影响点击 Start 进入原游戏。

## 现状与切入点

当前入口页由以下结构组成：

- [index.html](index.html)：定义 step-1 到 step-5 页面层级，首页菜单位于 `#step-1`
- [launch.js](launch.js)：负责首页交互、Start 按钮、帮助页、加载页和游戏初始化
- [css/multi.css](css/multi.css)：定义首页背景、标题、菜单和各 step 的样式

当前首页已经具备：

- 独立背景层 `#global`
- 标题层 `#title`
- 菜单层 `#menucontainer`

因此最稳妥的方案不是重写入口，而是在现有首页之前增加一层独立的“开屏序列层”，并在结束后显露原来的首页。

## 方案概述

采用“新增开屏层 + 保留原首页 + 受控切换”的方式实现。

### 核心原则

- 不改游戏核心逻辑：不改 `bkcore/hexgl/` 下的玩法和渲染逻辑。
- 最小侵入：只改入口页结构、首页样式、入口脚本与开屏相关资源。
- 可降级：若开屏资源加载失败，直接显示原首页，不阻塞用户开始游戏。
- 可跳过：任何时刻点击跳过，直接结束开屏并回到 `#step-1`。

## 视觉与分镜设计

### 开屏节奏（约 10 秒）

#### 0.0s - 2.5s：俯瞰霓虹城市

- 黑场淡入到城市夜景。
- 远景展示高楼轮廓、蓝紫霓虹边缘光、扫描光束与薄雾。
- 赛道发光轨迹在城市中若隐若现。
- 音频以低频环境氛围和远处电流声起步。

#### 2.5s - 5.0s：镜头压低掠过赛道

- 镜头快速下压，从俯瞰转为贴地前冲。
- 赛道边缘光、能量线、城市灯带形成残影。
- HUD 风格扫描线和轻微镜头抖动开始加入。
- 音频加入速度上升、风切和赛道能量扫过声。

#### 5.0s - 7.5s：飞船超近景掠过

- 飞船从镜头侧前方高速切入。
- 推进器逐级点亮，机体表面反射蓝紫霓虹。
- 镜头与飞船擦肩而过，强调近景压迫感。
- 音频进入高能段，引擎转速明显抬升。

#### 7.5s - 9.0s：引擎拉满与火花爆点

- 飞船贴着赛道压过一个高能点或边缘结构。
- 尾焰增强，出现短促火花与能量拖尾。
- bloom、辉光、速度线达到峰值。
- 音效加入擦地火花、推进器极限拉升与短促冲刺声。

#### 9.0s - 10.0s：转场回首页菜单

- 通过一道白蓝能量闪切或 HUD 扫描收束结束演出。
- 标题和菜单从扫描线/辉光中显现。
- 背景保留轻微动态待机，维持科技感。
- 开屏控制层隐藏，回到原来的 `#step-1` 首页交互。

## 界面结构设计

### 新增层级

在 [index.html](index.html) 中新增一个位于 `#step-1` 之前或更高 z-index 的开屏容器，例如：

- 开屏根层：承载整个动画流程
- 背景城市层：负责城市远景、雾、扫描光与天空渐变
- 赛道速度层：负责赛道光带、速度线、能量轨迹
- 飞船演出层：负责飞船近景切入和尾焰/火花
- HUD 特效层：负责扫描线、目标框、字幕闪现、转场特效
- 跳过按钮层：始终可点击
- 音频控制层：管理开屏专用音频

### 与现有首页的关系

- 现有 `#step-1` 保留不删。
- 页面初始时隐藏 `#step-1` 的可见性或让其在开屏层下方待命。
- 开屏结束后一次性显露 `#step-1`。
- `#step-1` 内的 Start、设置项、Credits 逻辑保持不变。

## 动画实现策略

### 推荐实现

使用 CSS 动画 + JavaScript 时间轴控制 + 现有背景资源增强，避免引入高风险渲染改造。

#### 原因

- 当前项目首页本身是 DOM/CSS 驱动，不是 Three.js 首页场景。
- 如果把开屏做成新的 WebGL 场景，会增加资源、状态切换和兼容性风险。
- 使用 DOM 分层、渐变、辉光、遮罩、位移、缩放、模糊和透明度变化，可以较低风险做出“科技 3D 感”。

### 视觉技术手段

- 多层渐变与发光遮罩模拟城市夜景深度
- 透视变换与位移动画模拟镜头推进和俯冲
- 速度线、扫描线、粒子闪烁模拟高速运动
- 飞船图层位移、缩放和 motion blur 风格效果模拟掠镜
- 转场使用全屏能量闪、扫描收束和标题淡入

### 音频策略

开屏音频与游戏正式音频解耦。

包含以下独立声层：

- 城市环境底噪
- 能量扫描 / 电流声
- 风切声
- 引擎预热与升转
- 火花擦地声
- 转场脉冲音

要求：

- 开屏结束或跳过时，开屏音频立即淡出并停止。
- 不影响后续游戏正式加载和播放。
- 若浏览器策略阻止自动播放，则首版允许静音开屏并保留视觉完整性。

## 交互设计

### 跳过逻辑

- 开屏开始后立即显示“Skip / 跳过”按钮。
- 用户点击后：
  1. 停止所有开屏计时器/动画状态
  2. 停止并淡出开屏音频
  3. 隐藏开屏层
  4. 显示首页 `#step-1`
- 跳过必须是幂等的，连续点击不会报错或重复切换。

### 首页待机态

开屏结束后，首页进入轻量动态状态：

- 背景可保留微弱流动和辉光
- 标题与菜单有更精致的出现动画
- 不再继续播放完整开场分镜

## 状态流转

入口状态机定义如下：

1. `opening`：开屏播放中
2. `opening_skipped`：用户中途跳过
3. `menu_ready`：首页菜单可交互
4. `help_ready`：点击 Start 后进入原 `#step-2`
5. `loading`：进入原 `#step-3`
6. `in_game`：进入原 `#step-4`

约束：

- 只有 `menu_ready` 状态允许用户操作首页菜单。
- `opening` 和 `opening_skipped` 必须完整回收开屏资源后，才进入 `menu_ready`。
- 原 `launch.js` 中 `start` 逻辑保持原流程，只在前面增加开屏完成门控。

## 资源设计

### 可新增资源

- 开屏背景图层素材
- 飞船近景剪影或高亮贴图
- 扫描线 / HUD 叠层纹理
- 火花粒子小贴图
- 开屏专用短音效

### 不改动资源

- 现有赛道、船体玩法模型与比赛阶段资源不做功能性修改
- 不替换游戏内赛道逻辑
- 不更改比赛中的摄像机或控制器实现

## 错误处理与降级

### 必须处理的情况

- 开屏资源缺失：直接进入首页
- 音频自动播放失败：静音播放视觉版开屏
- 用户快速连点跳过：只执行一次退出逻辑
- 窗口尺寸变化：开屏层保持铺满，不阻塞后续首页

### 明确不做

- 不为老旧浏览器单独补做复杂兼容分支
- 不在首版中加入多段分支剧情或动态菜单逻辑
- 不改造为完整 3D 实时首页场景

## 测试设计

### 功能验证

- 页面打开后自动进入开屏
- 开屏自然结束后进入首页
- 任意时刻点击跳过都能进入首页
- 首页 Start 仍能进入帮助页与正式加载流程
- Credits、画质、控制方式等菜单功能保持可用

### 视觉验证

- 城市 → 赛道 → 飞船 → 火花 → 菜单的节奏完整可感知
- 标题和菜单在转场后仍清晰可读
- 跳过时不会闪黑、残留图层或卡住输入

### 音频验证

- 开屏音频能正常启动时，层次符合节奏推进
- 跳过时开屏音频会停止
- 游戏后续不出现双重音频叠加

## 首版范围控制

首版只追求“稳定、好看、可跳过、无侵入”。

明确包含：

- 10 秒左右开屏
- 城市、赛道、飞船、火花、HUD 转场
- 跳过按钮
- 首页承接动画
- 开屏独立音效

明确不包含：

- 真实 Three.js 首页漫游场景
- 游戏内实时摄像机动画改造
- 复杂可配置开屏系统
- 多版本随机片头

## 设计结论

这次升级应当把 HexGL 的静态首页改造成“先演出、后菜单”的入口体验：先用霓虹城市建立世界，再用高速赛道和飞船近景完成爆点，最后平滑回到原首页，并保留原有开始游戏流程不变。首版以 DOM/CSS/JS 时间轴实现，风险最低，也最符合“不改坏游戏本身”的要求。
